# Q1 - C Program Development and Compilation for a sensor monitoring system
## What the program does
The program models the processing step of a water quality device monitor by receiving two sensor readings which are
temperature in °C and turbidity in NTU. It combines them into a single water quality index and then takes that 
index into a three status bands and shows the result in a fomratted manner

## Program structure
The program is devided into 4 functions + `main()` which makes each job modularized and isolated
for easy reading and test.
the functions are:
- **`temperature_deviation()`**: calculates the absolute temperature minus 25
- **`turbidity_penalty`**: calcualte the turbidity penalty by dividing to 2
- **`water_quality_index()`**: calls two functions above to get the final index
- **`classify_quality()`**: performs the classification logic into Good, Warning and Critical
- **`print_report()`**: formats and prints the monitoring report

### Real-World application of C in embedded or systems-based programming

#### Application
This program stands in a the firmware of the monitoring device itself.
Its sensor node is built around a small 8-bit microcontroller like an ATmega328P on an Arduino Uno;
which is the C firmware that samples the sensor, calculates index and the drives the outputs.

So basically C is good for this because:
- **It compiles to native machine code** as there is no need for an interpreter which gives the programmer control over deterministic timing
- **There is no garbage collector** as the memory is allocated and freed easily
- **It has a very small memory footprint** which shows how C lets a programmer decide exactly what is stored where
- **It is able to directly access the hardware** which shows how C expreses naturally thru pointers and fixed addresses
- **It ensures portability without losing low-level control** 
- **Its mature and a long lived toolchain**

### Error analysis
#### Syntax error example
```c
float index = 100.0f - ((temperature - 25.0f) + (turbidity / 2.0f))
printf("Index = %.2f\n", index);
```

and gcc returns:

```c
q1_syntax_error.c:19:3: error: expected ',' or ';' before 'printf'
   19 |   printf("Index = %.2f\n", index);
      |   ^~~~~~
(gcc exit code = 1)
```

**This is to say** that the compiler parses the source as a sequence of tokens and that a declaration statement in C must end with a `;`.
with its absence the line `float index = ...) printf(` mismatches C grammar and the compiler detects this and refuses to produce an object file because of this
**grammar mistake**

#### Semantic Error example

```c
int turbidity = 5;             /* should be float / double */
float penalty = turbidity / 2; /* 5 / 2 is 2, not 2.5 */
```

and with gcc -Wall -Wextra it gives:
```c
Turbidity: 5 NTU
Formula wants: 5 / 2 = 2.50
Code actually got: 2.00
```

**This is to say that** every token is legal and the statement parses but if we look at what the code means, we find that `/` operator applied to two ints
do truncates integer division, which gives 2 instead of 2.5. So this kind of error is found only by testing and reasoning about the code which is why the output
was checked against a hand-computed values at each step.

### The compilation lifecycle
A compilation lifecycle follos 4 stages done by toolchain and a fifth one which is performed at runtime by the OS.
1. **Step 1 - Preprocessing**: 
 - cmd: `gcc -E waterquality.c -o waterquality.i`
 - Input: waterquality.c file with its 2 headers
 - Operation: every `#include` and `#define`gets replaced by the contents of its header and no C is analysed 
 - Output: waterquality.i is now expanded with more lines of the pasted in headers
2. **Step 2 - Compilation**: 
 - cmd: `gcc -S waterquality.i -o waterquality.s`
 - Input: waterquality.i file is preprocessed with `.i` file
 - Operation: a syntax analysis happens and build a parse tree , semantic analysis checks names and types use if is consistent and then emits instructions for the target processor
 - Output: assembly language source gets created through a file

3. **Step 3 - Assembling**: 
 - cmd: `gcc -c waterquality.s -o waterquality.o`
 - Input: waterquality.s file
 - Operation: the file content is translated into machine-code bytes.
 - Output: an object file waterquality.o is created and its relocateble

4. **Step 4 - Linking**: 
 - cmd: `gcc waterquality.o -o waterquality.lm`
 - Input: waterquality.o object file, plus the necessary libraries
 - Operation: the linker merges object files by matching every symbol to a definition in a library and performs relocation so that addresses become final
 - Output: waterquality.lm is now executable

5. **Step 5 - Loading**: 
 - Input: the executable file
 - Operation: the Operating Sys maps the program into memory
 - Output: a running process
