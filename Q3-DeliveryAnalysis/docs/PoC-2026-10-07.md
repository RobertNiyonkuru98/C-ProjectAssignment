# Q3 : Functions & Recursive Problem Solving

## 1. What the program does

The logistics company records the distance of each delivery route as a whole
number of kilometres. The program collects those numbers into an integer array
and reports the total distance, the average distance, the longest route, the
number of routes longer than a chosen limit, and the total once more => this time
computed **recursively** rather than with a loop.

## 2. Sample output from the brief's example

Input: 6 routes =>> `12 25 18 40 15 30` =>> with a distance limit of `20`.

```
===== DELIVERY DISTANCE ANALYSIS =====

Total distance: 140 km
Average distance: 23.33 km
Longest route: 40 km
Routes above 20 km: 3

Recursive sum: 140 km

--- function reuse demonstration ---
count_above_limit() is called a second time, with a different limit
(the average distance, 23 km instead of 20 km):
Routes above 23 km: 3
```

These values match the results quoted in the brief (`140`, `23.33`, `40`, `3`).

## 3. How the program is divided into functions

Each job is delegated to a separate function, so `main()` does nothing but read
input and print results. That makes every calculation individually readable and
individually testable.


- `total_distance(const int distances[], int n)` => adds each element with a `for`
  loop and returns the sum.
- `average_distance(const int distances[], int n)` => **reuses** `total_distance()`
  rather than summing again, then divides by `n`. The cast `(double)` before the
  division is deliberate: without it, `int / int` would truncate the average.
- `longest_route(const int distances[], int n)` => starts from the first element and
  keeps the largest value seen.
- `count_above_limit(const int distances[], int n, int limit)` => takes the limit as
  a **parameter**, which is what allows the same function to be reused for a
  different limit.
- `recursive_sum(const int distances[], int n)` => the required recursive function.
- `main()` => reads `n`, the distances and the limit, then prints the results.

**Function reuse, in two distinct forms.** The brief asks for reuse demonstrated
"by calling an appropriate function more than once with different arguments **or**
using a function as part of another calculation". This program does both:

1. *Used as part of another calculation* => `average_distance()` calls
   `total_distance()` internally instead of duplicating the summing loop.
2. *Called more than once with different arguments* => `count_above_limit()` is
   called once with the user's limit (`20`) and then again with the average
   distance (`23`), producing `3` both times from the same function.

## 4. How the recursive function works

```c
int recursive_sum(const int distances[], int n) {
  if (n == 0) {
    return 0;                                          /* BASE CASE */
  }
  return distances[n - 1] + recursive_sum(distances, n - 1);
}
```

The brief sets three conditions for the recursive function. Each is met explicitly:

**a) It has a clear base case.** `if (n == 0) return 0;`. An array with no elements
has a sum of zero, and this is the point at which the function stops calling
itself. Without a base case the recursion would never terminate.

**b) It reduces the problem toward the base case on every call.** The recursive
call is `recursive_sum(distances, n - 1)`. Because the second argument is always
exactly one smaller than the current `n`, every call moves one step closer to
`n == 0`. The array itself is never copied or modified => only the *count of
elements still to add* shrinks.

**c) It correctly returns the result to the calling function.** Each call returns
one value: the last element **plus whatever the next call returned**. The partial
sums are handed back up the chain until the original call returns the complete
total. Nothing is printed inside the recursion; the value is purely returned.

### Tracing `recursive_sum({12, 25, 18, 40, 15, 30}, 6)`

```
recursive_sum(n=6) -> 30 + recursive_sum(n=5)
                    -> 30 + 15 + recursive_sum(n=4)
                    -> 30 + 15 + 40 + recursive_sum(n=3)
                    -> 30 + 15 + 40 + 18 + recursive_sum(n=2)
                    -> 30 + 15 + 40 + 18 + 25 + recursive_sum(n=1)
                    -> 30 + 15 + 40 + 18 + 25 + 12 + recursive_sum(n=0)
                    -> 30 + 15 + 40 + 18 + 25 + 12 + 0
                    =  140
```

The arrow that finally returns `140` is the same expression being collapsed, one
frame at a time, as the base case unwinds.

## 5. Advantage and limitation of using recursion here

**Advantage => the code mirrors the problem.** The definition of a sum is naturally
recursive: *the sum of n items is the last item plus the sum of the first n-1
items*. The recursive function states that idea directly, in two lines, with no
loop counter, no accumulator variable and no off-by-one index to get wrong. It is
concise, easy to read, and it is straightforward to argue formally that it is
correct by induction on `n`.

**Limitation => it costs stack space and it does not scale.** Every call creates a
new stack frame that is held until its recursive call returns, so `recursive_sum()`
uses O(n) memory in the worst case, whereas the loop-based `total_distance()` uses
a single fixed frame. For an array of 100,000 routes the recursion would be liable
to overflow the stack and crash; the iterative version never would. It is also
slower for the same reason => a function call per element instead of a simple
add-and-branch. In this program the risk is bounded because the array is capped at
`MAX_ROUTES` (100), but as a general technique recursion is the less safe choice
when the input size is not guaranteed to stay small. C does not promise to
eliminate the extra frames, so the loop remains the more robust option for
unbounded data.
